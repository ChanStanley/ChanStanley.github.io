The path an HTTP request takes from a browser to my GitHub Pages site can be broken down to a couple of steps. 
The HTTP request only happens after the browser and the web server, in our case it is the GitHub Pages server has established a connection. This HTTP request has important information such as browser type and a GET command in this case, where we are trying to GET the URI. When the server receives this request, it will send back the requested items or respond with an error if the server does not find those items and that is called an HTTP response. The browser will finally render the items and we have our pages site.

A Docker container is different from the environment that GitHub Pages provides as they have two different purposes. GitHub Pages provides a fixed environment that only holds static files. Docker containers are running instances of docker images, which includes all of your source code, services, etc. which allows for other people to have the same setup as you. Essentially, Docker containers provides a lot more flexibility than GitHub Pages as GitHub Pages requires more effort in obtaining the same setup.
